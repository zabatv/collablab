# Контракт API магазина-витрины

Два HTTP-сервера на одной базе. Все ответы в JSON (UTF-8), даты в ISO 8601 (UTC), деньги числом в рублях с копейками.

| Сервер | Адрес в разработке | Кому | Что можно |
|---|---|---|---|
| Публичный API | `http://127.0.0.1:3000`, в продакшене `https://<домен витрины>` | витрина (сайт) | только чтение, только активные товары |
| Сервер админки | `http://127.0.0.1:3001` | фронтенд админки | чтение с служебными полями и запись |

Ошибка любого запроса: статус 400/401/403/404/409/413/500 и тело `{"error": "<текст на русском, можно показать пользователю>"}`. У 409 дополнительно `code` и `existing`.

## Публичный API (порт 3000)

Только `GET`. CORS разрешён для домена из `CORS_ORIGIN`. Скрытые товары (`is_active = false`) не отдаются ни списком, ни по id (404).

### `GET /health`

`{"status": "ok"}`. 500, если база недоступна.

### `GET /products`

| Параметр | Описание |
|---|---|
| `category` | slug или id категории. Товары вложенных категорий включаются. Неизвестная категория даёт 404 |
| `search` | подстрока в названии или артикуле, без учёта регистра, до 100 символов |
| `in_stock` | `true` = только с остатком больше нуля |
| `sort` | `name` (по умолчанию), `-name`, `price`, `-price`, `-updated`. Товары без цены в конце |
| `page`, `limit` | пагинация, по умолчанию 1 и 24, максимум `limit` = 100 |

Неверное значение параметра даёт 400.

```json
{
  "items": [{
    "id": 45, "article": "PL4-18", "name": "Фитинг угловой, 4мм x G 1/8",
    "price": 75, "quantity": 12, "in_stock": true,
    "category": {"id": 1, "name": "Фитинг", "slug": "fiting"},
    "photo": "/media/products/pl4-18-15521efe.jpeg",
    "updated_at": "2026-09-17T12:06:22.476Z"
  }],
  "total": 110, "page": 1, "limit": 24, "pages": 5
}
```

- `price: null` означает «цена по запросу», на витрине показывать текст вместо цены.
- `photo` это первое фото товара или `null`.
- `category` может быть `null`.

### `GET /products/:id`

Те же поля, плюс `description` (текст с переносами строк `\n`) и `media`, вместо `photo`:

```json
{
  "id": 45, "article": "PL4-18", "name": "...", "description": "Латунь.\nРезьба G 1/8.",
  "price": 75, "quantity": 12, "in_stock": true,
  "category": {"id": 1, "name": "Фитинг", "slug": "fiting"},
  "media": [
    {"id": 10, "url": "/media/products/pl4-18-15521efe.jpeg", "type": "photo", "sort_order": 0},
    {"id": 11, "url": "/media/products/pl4-18-9a1c02f0.mp4", "type": "video", "sort_order": 1}
  ],
  "updated_at": "2026-09-17T12:06:22.476Z"
}
```

`media` отсортирован по `sort_order`. `type` это `photo` или `video`. Нечисловой id даёт 400, неизвестный или скрытый товар 404.

### `GET /categories`

```json
{"items": [{"id": 1, "name": "Фитинг", "slug": "fiting", "parent_id": null, "products_count": 110}]}
```

Плоский список, отсортирован по имени. Дерево собирается по `parent_id`. `products_count` считает активные товары только самой категории, без вложенных.

### `GET /media/...`

Файлы фото и видео. Ссылки в API относительные (`/media/products/...`): витрина подставляет перед ними базовый адрес API. Если на сервере задан `MEDIA_BASE_URL`, ссылки приходят абсолютными. Кэшируются на 7 дней.

## Сервер админки (порт 3001)

### Доступ

- Запросы из браузера принимаются только со страниц, чей origin вписан в `ADMIN_ALLOWED_ORIGINS` на сервере (`http://localhost:5173` и `http://127.0.0.1:5173` это разные origin). Иначе: `GET` блокируется CORS в браузере, запись получает 403.
- Если задан `ADMIN_PASSWORD`, каждый запрос несёт `Authorization: Basic base64(ADMIN_USER:ADMIN_PASSWORD)`, иначе 401. Локально пароль обычно пуст.
- Preflight `OPTIONS` обрабатывается сервером: методы `GET, HEAD, POST, PATCH, PUT, DELETE`, заголовки `Content-Type`, `Authorization`. Заголовок ответа `Location` доступен из JavaScript.
- Тело JSON до 256 КБ, иначе 413.

### Чтение

`GET /products`, `GET /products/:id`, `GET /categories` те же, что в публичном API, с отличиями:

- Видны скрытые товары.
- У товара три служебных поля: `is_active` (показывать на витрине), `manually_edited` (название, описание и категория защищены от 1С), `is_linked_to_1c` (товар привязан к записи 1С).
- В списке дополнительный фильтр `linked_to_1c=true|false`. `false` показывает товары, у которых цена и остаток из 1С не обновляются: их стоит пометить в интерфейсе.

### `POST /products` — создать товар

Только так появляются новые товары: синхронизация из 1С товары не создаёт.

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| `article` | string | да | До 100 символов, пробелы по краям и двойные убираются. Хвост складской ячейки 1С ` *3*7*34` отсекается. После создания не меняется |
| `name` | string | да | Непустое, до 500 символов |
| `description` | string | нет, `""` | До 20 000 символов, переносы строк сохраняются |
| `category_id` | integer или `null` | нет, `null` | id из `GET /categories` |
| `price` | number или `null` | нет, `null` | Больше 0, округляется до копеек. `null` = «цена по запросу». Строки и 0 не принимаются |
| `is_active` | boolean | нет, `true` | `false` создаёт скрытым |

Другие поля дают 400. Остаток при создании 0: дальше остаток и цену ведёт 1С.

Ответ **201**, заголовок `Location: /products/<id>`, тело в формате `GET /products/:id` админки:

```json
{
  "id": 300, "article": "TKC-PY-4", "name": "Тройник", "description": "",
  "price": 1100, "quantity": 0, "in_stock": false,
  "category": {"id": 3, "name": "Фитинги", "slug": "fitingi"},
  "media": [], "updated_at": "2026-09-18T13:00:00.000Z",
  "is_active": true, "manually_edited": true, "is_linked_to_1c": false
}
```

| Код | Когда | Дополнительно |
|---|---|---|
| 400 | нет `article` или `name`, неверный тип, лишнее поле, длина, несуществующая категория, битый JSON | |
| 409 | `code: "article_exists"`: такой артикул есть | `existing: {id, article, name}` |
| 409 | `code: "article_similar"`: артикул отличается от существующего только регистром, пробелами, дефисами, знаками (`fa40` при `FA-40`) | `existing: {id, article, name}` |

```json
{"error": "Товар с артикулом «FA40» уже существует", "code": "article_exists",
 "existing": {"id": 261, "article": "FA40", "name": "Монтажный фланец"}}
```

По `existing.id` предложить открыть существующую карточку. Рядом с полем артикула нужна подсказка: «Введите артикул точно как в 1С, иначе цена и остаток не подтянутся при синхронизации». `is_linked_to_1c` станет `true` после ближайшей синхронизации, если 1С нашла товар по артикулу.

### `PATCH /products/:id` — изменить товар

Тело: любое подмножество `{name, description, category_id, is_active, manually_edited}`. Правила полей как в POST. Неизвестные поля дают 400: цену, остаток, артикул менять нельзя.

- `manually_edited` поднимается в `true` сам, если `name`, `description` или `category_id` реально изменились. `is_active` его не поднимает.
- Явно переданный `manually_edited` имеет приоритет над автоматическим. `manually_edited: false` возвращает товар под управление 1С: при следующей синхронизации 1С перезапишет название, описание и категорию. Если в том же запросе прислать и правки содержимого, они сохранятся, но флаг останется `false`, и 1С их затрёт. В интерфейсе эти два действия лучше не совмещать.

Ответ 200: карточка товара плюс `changed`, массив имён реально изменившихся полей, например `["name", "manually_edited"]`. Пустой массив, если ничего не изменилось. 404, если товара нет.

### `POST /products/:id/media` — загрузить фото и видео

`multipart/form-data`, поле `files`, несколько файлов за раз (до `MAX_UPLOAD_FILES`, по умолчанию 10). `Content-Type` вручную не задавать, его выставит браузер.

- Тип определяется по содержимому: JPEG, PNG, WebP, MP4, WebM. SVG, MOV, HEIC отклоняются с объяснением.
- Лимиты: фото `MAX_PHOTO_MB` (10), видео `MAX_VIDEO_MB` (200). Превышение даёт 413.
- Всё или ничего: одна плохая картинка отменяет всю загрузку.
- Файлы добавляются в конец, имя на диске задаёт сервер. Первое по порядку фото становится главным (`photo` в списке).

Ответ **201**: карточка товара с обновлённым `media`.

### `DELETE /products/:id/media/:mediaId`

Удаляет запись и файл. Ответ 200: карточка товара. 404, если медиа не у этого товара.

### `PUT /products/:id/media/order`

Тело `{"ids": [3, 1, 2]}`: полный список id медиа товара в новом порядке. Неполный или чужой список даёт 400. Ответ 200: карточка товара.

Изменение медиа не поднимает `manually_edited`.

## Чего не хватает: категории

Категории можно только читать. Создать, переименовать, перенести или удалить
через API нельзя — таких эндпоинтов нет, и админка честно говорит об этом
вместо того, чтобы делать вид, что кнопка работает.

Заказчику это нужно: ассортимент растёт, и раскладывать его по полкам он
хочет сам. Таблица к этому готова — `parent_id` держит любую вложенность, а
сайт показывает третий уровень: хлебные крошки, плитки, дерево в админке
(проверено).

Чего ждём на стороне бэкенда, в том же стиле, что и товары:

### `POST /categories` — создать

| поле | тип | обяз. | |
|---|---|---|---|
| `name` | string 1..100 | да | |
| `parent_id` | integer или `null` | нет, `null` | id существующей категории, иначе 400 |
| `slug` | string | нет | если не прислан — собрать самим, уникальность за сервером |

Ответ **201**, `Location: /categories/<id>`, тело в формате `GET /categories`.
409, если в том же родителе уже есть категория с таким именем.

### `PATCH /categories/:id` — переименовать или перенести

Поля те же, все необязательные. Перенос внутрь собственной ветки — 400,
иначе дерево замкнётся само на себя.

### `DELETE /categories/:id`

400, если в категории есть товары или вложенные категории: удалять молча
вместе с содержимым опаснее, чем отказать.

Пока этого нет, категории пишет сервис сайта — напрямую в базу каталога, с
теми же проверками, что описаны выше (`CATALOG_DB`, см.
docs/deploy-robots07.md). Это обход, а не замена: как только эндпоинты
появятся, сайт переключится на них, а прямой доступ к базе уйдёт.

## Что важно знать фронтендам

- **Цена и остаток принадлежат 1С.** Через API их не изменить, они обновляются синхронизацией по расписанию.
- **`price: null` это «цена по запросу»**, не ноль и не ошибка.
- **Ссылки на медиа относительные.** Перед `/media/...` подставляется базовый адрес того сервера, к которому ходит фронтенд.
- **Категории в 1С пока не ведутся**, список из `GET /categories` управляется на стороне сайта.
- **Пример запроса из фронтенда админки:**

```js
const API = 'http://127.0.0.1:3001'; // из настройки фронтенда
const res = await fetch(`${API}/products`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ article: 'TKC-PY-4', name: 'Тройник' }),
});
if (res.status === 409) { const { code, existing } = await res.json(); /* открыть existing.id */ }
```
