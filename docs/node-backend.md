# Подключение сайта к их бэкенду (Node + PostgreSQL)

Сайт умеет работать с двумя бэкендами: нашим (Flask, порт 5000) и их
(Node + PostgreSQL, два сервера — публичный 3000 и админский 3001).
Переключатель один, в `frontend/js/config.js`:

```js
window.SHOP_CONFIG = {
  backend: 'flask',          // 'node' — их бэкенд
  node: {
    public: 'http://127.0.0.1:3000',   // адрес публичного API
    admin:  'http://127.0.0.1:3001',   // адрес админского API
  },
};
```

Страницы про это не знают: они, как и раньше, ходят через `ProductAPI` и
`AdminAPI`. Перевод форматов лежит в `frontend/js/adapter-node.js`.

## Что переводится

| У нас | У них |
|---|---|
| `product.sku` | `article` |
| `product.stock` | `quantity` |
| `product.image`, `images`, `videos` | `photo`, `media[]` с `type` |
| дерево категорий с `total_count` | плоский список, дерево собирается на сайте |
| токен в заголовке `Bearer` | HTTP Basic в каждом запросе |
| `PUT /admin/products/:id` целиком | `PATCH /products/:id` подмножеством полей |

Счётчики по ветке (`total_count`) считаются на сайте: их `products_count`
считает только саму категорию, без вложенных.

Фотографии всегда запрашиваются у **публичного** сервера, даже из админки:
он отдаёт файлы без пароля, а заголовок авторизации браузер к `<img>` не
приложит.

## Чего у них нет

Бренды, слайдер на главной, характеристики таблицей, «исполнения» товара,
Excel-импорт и экспорт, SEO-раздел, статистика просмотров, удаление товара
и правка категорий.

На витрине эти блоки просто не показываются. В админке разделы «Слайдер»,
«Бренды» и «SEO» скрыты, кнопки Excel убраны, а кнопка удаления объясняет,
что товар нужно снимать с витрины галочкой «Показывать на витрине».

Цена, остаток и артикул после создания принадлежат 1С — поля заблокированы
с подписью почему. Название, описание и категорию правит сайт, и первая же
такая правка поднимает их флаг `manually_edited`, после чего 1С эти поля не
перезаписывает.

## Категории: дерево переносится напрямую в базу

Их категории берутся из классификатора 1С, а пока его нет — из первого слова
названия товара («Фитинг», «Клапан», «Прочее»), плоским списком. Эндпоинтов
для правки категорий в API нет, так что через сайт дерево не построить.

Но таблица `categories` у них с `parent_id` — такая же, как наша. Поэтому
дерево переносится SQL-файлом, мимо API:

```bash
python3 scripts/postgres_tree.py -o tree.sql
psql -U shop -d shop -f tree.sql      # на их машине
```

Файл в одной транзакции создаёт наши категории, переставляет товары по
артикулу (точному, затем по мягкому ключу — `FA40` против `FA-40`, только
однозначные пары) и удаляет их прежние категории, оставшиеся пустыми.
Категории, в ветке которых нет ни одного товара, не создаются. Перед
`COMMIT` печатается отчёт: сколько создано, сколько товаров встало в дерево,
какие артикулы не нашлись и сколько товаров в каждом разделе.

Повторный запуск отказывается работать: дерево создалось бы вторым
комплектом рядом с первым.

Проверено на настоящем PostgreSQL с их схемой и нашими 299 товарами,
разложенными по их правилу «первое слово названия»: 52 категории, 11
разделов, все 299 товаров в дереве, ни одного без категории, счётчики по
разделам совпали с нашим сайтом.

## Что нужно на их стороне

- `CORS_ORIGIN` — origin сайта (например `https://robot-kbr.ru`), иначе
  браузер не отдаст ответы публичного API.
- `ADMIN_ALLOWED_ORIGINS` — тот же origin для страницы админки. Учтите, что
  `http://localhost:5173` и `http://127.0.0.1:5173` — разные origin.
- `ADMIN_USER` и `ADMIN_PASSWORD` — логин и пароль, которые вводятся на
  странице входа сайта.
- Админский сервер слушает `127.0.0.1`. Если сайт открывают не с той же
  машины, до порта 3001 нужно дотянуться — через обратный прокси или
  туннель. Наружу его выставлять нельзя: там HTTP Basic и никакой защиты
  от подбора.

## Проверка без их сервера

`scripts/mock_node_api.py` — заглушка их API по `docs/api-contract.md`:
те же поля, коды ошибок и правила. Работает с копией нашей базы во
временном файле, настоящий каталог не трогает.

```bash
python3 scripts/mock_node_api.py --password secret
# :3000 витрина, :3001 админка
```

Дальше в `config.js` поставить `backend: 'node'`, открыть сайт и войти с
тем же паролем. Проверено на заглушке: каталог, разделы главной, поиск,
карточка товара, вход, список товаров в админке, создание товара, отказ по
совпадающему артикулу (409 с предложением открыть существующую карточку),
правка названия с автоматическим `manually_edited`.

Заглушка — для проверки фронтенда, не для продакшена: пароль сверяется без
защиты от подбора, CORS открыт всем.
